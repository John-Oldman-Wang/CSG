# notify — 提醒层

## 做什么

飞书机器人推送。**分级是生死线。**

## 怎么做

### 不分级的提醒系统会自己失效

三个月后用户会开始无视所有推送，等于系统白做。故分两个群：

| 级别 | 场景 | 渠道 |
|---|---|---|
| P0 | 证伪条件命中、财报暴雷、政策冲击持仓行业 | CSG-紧急群，强提醒 |
| P1/P2 | 复核任务、观察池到价、周报 | CSG-日常群，普通通知 |

**混在同一个群会导致用户静音整个群**——那时 P0 也一起失效了。

### 能力边界

| 消息类型 | 可行性 |
|---|---|
| 文本 / 富文本 | ✅ |
| 交互式卡片（展示） | ✅ |
| 卡片按钮回调 | ❌ 需公网 IP，MacBook 没有 |

因此交互模型是：**飞书负责「告诉你要做什么」，判断和记录回到电脑上用 CLI 完成。**

### 去重与限频

同一事件不重复推送、同一标的当日限频。`notification_log` 记录每次发送，
既是去重依据也是事后排查线索。

## 安全

Webhook URL 即凭证，写在 `config/secrets.yaml`（已 gitignore）。
建议开启飞书的**签名校验**——泄露的后果是他人可向群内发消息
（只能写、不能读取群内容），属骚扰风险而非数据泄露。
