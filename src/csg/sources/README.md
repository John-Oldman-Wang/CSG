# sources — 数据源适配

## 做什么

把不稳定的免费数据源封装成可靠接口。**故障是常态而非例外。**

```
base.py              容错基础设施：强制超时、限速、退避重试、熔断、多源 fallback
akshare_source.py    财报（含披露日）、研报、股票列表、行业分类
baostock_source.py   行情、复权因子、历史 PE/PB/PS
```

## 怎么做

### 三源分工

| 源 | 角色 | 原因 |
|---|---|---|
| akshare（东财） | 财报 + 研报 | 唯一提供商誉/在建工程/合同负债/资本开支的源 |
| baostock | 行情 + 估值 | 非爬虫架构，不受东财 IP 限流影响 |
| 巨潮 | 抽样校验 | 一手权威，用于验证披露日期准确性 |

### Point-in-Time 锚点（已实测验证）

东财**按报告期**详细接口的 `NOTICE_DATE` 是财报首次披露日，
经巨潮原始公告交叉核对一致（宁德时代 2021 年报双方均为 2022-04-22）。

⚠️ **切勿改用批量接口**（`stock_lrb_em` 等）的「公告日期」——
实测与查询的报告期错位（查 2024Q3 返回 2026 年日期），
用于 PIT 会静默产生未来函数。

## 坑

**请求会无限挂起。** `socket.setdefaulttimeout` 解决不了：urllib3 建连后会用
requests 的 timeout 覆盖全局默认，而 akshare 显式传 `None`。必须 monkey patch
`requests.Session.request` 把 None 替换为有限值。

**重试对「永不返回」无效**——它只能捕获抛出的异常。超时是重试能生效的前提。

**东财按 IP 限流**，触发后所有接口一并失效，换接口无用，只能换数据服务商。
实测 0.6 秒间隔连续二十次即触发，故全局最小间隔设 1.5 秒 + 连续失败熔断。

**两源复权算法不一致**，同一只股票不可混用，否则拼接处会产生虚假价格跳变。
