# validation — 验证层

## 做什么

用历史数据检验系统里的每一条假设。**产出常常是「这个不能用」——
那正是它的价值。**

```
flag_backtest.py    验证① 红旗规则能否提前发现暴雷
cycle_study.py      验证② 行业周期规律
screen_backtest.py  验证③ 筛选条件历史表现
research_study.py   验证④ 研报是否有预测力
store.py            结果持久化（含数据快照）
```

## 怎么做

### 过拟合防线写死在代码里，不做成可选项

```
发现期  2018-01-01 ~ 2022-12-31
验证期  2023-01-01 ~ 至今
```

**任何在验证期不成立的结论一律不予采信。** 事先定死，
否则事后总能给自己找到理由。

### 结果必须落库并附数据快照

回测依赖当时的数据状态，而数据在持续增长——同一段代码下月跑出的
数字会不同。没有快照就无法解释差异来自代码还是数据。

```
validation_run         参数 + 数据快照
validation_result      结构化指标
validation_conclusion  人工判定（adopted / rejected / pending）
```

**被否定的结论同样保留**：记住哪些假设失败过，与记住哪些成立同样重要。

## 已有结论（截至 2026-08-16）

| 发现 | 判定 | 依据 |
|---|---|---|
| 评级本身有预测力 | ❌ rejected | 买入评级 7506/5921 样本，超额恒为 0.0000，胜率 49% |
| 评级下调有信息量 | ❌ rejected | 发现期 +8.09%，验证期 −10.72%，符号完全反转 |
| 机构准确率可作权重 | ❌ rejected | 秩相关 −0.286，前 1/3 留存率 0.143（随机基准 0.333） |
| 红旗规则可提前识别暴雷 | ⚠️ pending | 覆盖率 58.7%、提前 730 天，但误报率 81-98% |
| 追涨型研报是反向指标 | ⚠️ pending | 60 日尺度两期同向，250 日不一致，疑为市场短期反转效应 |

**没有一条 adopted。** 三个验证都在说「这个还不能用」，
而不是给出漂亮数字让人放心下注。

## 重要限制

验证③ **只能验证机械筛选层，不是方法论**。护城河判断、买入理由、
证伪条件、复核决策占了方法论的大部分，历史上没有记录、无法重现。
若它跑出漂亮的收益率，**不构成对方法论的验证**——
把它当成验证通过，比不做回测更危险。
