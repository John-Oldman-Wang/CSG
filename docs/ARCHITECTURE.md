# CSG 架构设计

个人 A 股投研系统。本文档定义系统分层、模块职责与技术选型。

> **设计约束**：这是个人项目，不是机构系统。所有设计以「一个人能维护、能跑得动、不骗自己」为准，
> 不追求可扩展性、高可用、微服务。宁可少做，不做半吊子。

---

## 一、核心设计原则

### 1. 分层单向依赖
上层依赖下层，下层不知道上层存在。数据层不应该知道「止损」是什么。

### 2. 事实与判断分离
- **事实**（可计算、可验证）：股价、ROE、现金流、政策发布时间 → 交给代码
- **判断**（需要理解和推理）：护城河、管理层、行业前景 → 交给人，系统只负责记录和提醒复查

系统的职责是**把事实整理好递到你面前**，不是替你判断。任何模块如果开始输出「建议买入」，说明它越界了。

### 3. 「读数」与「预测」严格区分
系统只提供当前状态的读数（估值分位、利率水平、财务指标），不做任何未来预测。
预测由人做，并且必须写进决策日志，事后可被复盘检验。

### 4. 所有决策可追溯
每一笔交易必须能回答：当时为什么买、假设是什么、用的哪版规则、事后是否被证伪。
没有这条，系统无法自我改进。

### 5. 下跌触发「调查」，不触发「动作」
本系统采用**混合派**定位（详见 L6 监控层）。价格下跌本身不构成任何买卖信号，
它触发的是一个**待办复核任务**：判断这是情绪面还是价值面。
系统不做这个判断，系统负责把判断所需的材料准备好并盯着你别拖延。

## 二、分层架构

```
┌─────────────────────────────────────────────────────────┐
│  L9  接口层        CLI · 报告生成 · （后期）Web 看板      │
├─────────────────────────────────────────────────────────┤
│  L8  复盘层        交易流水 · 绩效归因 · 纪律统计         │  ← 反哺 L4/L5/L6

│  L7  提醒层        分级 · 去重 · 推送渠道                 │
├─────────────────────────────────────────────────────────┤

├─────────────────────────────────────────────────────────┤
│  L5  决策层        仓位规则 · 组合约束 · 决策日志         │
├─────────────────────────────────────────────────────────┤
│  L4  研究层        估值测算 · 观察池 · 买入理由           │
├─────────────────────────────────────────────────────────┤

```

## 三、各层职责

### L1 数据层 — 地基

**这层做不扎实，上面全废。工作量占比预计 40%，不要低估。**

| 模块 | 职责 |
|---|---|
| `sources/` | 数据源适配器，统一接口。akshare / baostock / tushare 各一个实现 |
| `storage/` | 本地存储与读取 |
| `pipeline/` | 增量更新、失败重试、断点续传 |
| `quality/` | 数据校验 |

**必须处理的坑（按踩坑概率排序）：**

1. **复权** — 前复权/后复权/不复权三套价格的用途不同。
   - 计算技术指标、回测 → 后复权（前复权会因新的除权事件改变历史值）
   - 展示给人看 → 前复权
   - 计算实际盈亏 → 不复权 + 单独记录分红送股
   - **存原始价格 + 复权因子，用时再算**，不要直接存复权价

2. **财报的实际公布时间** — 数据里的「报告期」是 2024Q3，但公布日可能是 2024-10-28。
   任何用到财报的计算，时间轴必须以**公布日**为准，否则就是未来函数。这是最隐蔽的 bug。

3. **股票池的时点正确性** — 回测/统计时要用「当时的」股票列表，不能用今天的。
   否则退市股、ST 股被排除在外，形成幸存者偏差。需要维护股票状态的时间序列。

4. **停牌、ST、退市、更名、拆并股** — 代码复用、名称变更都会导致数据错配，用不变的代码 + 时间段来标识。

5. **数据源交叉验证** — 免费源经常出错。关键字段（收盘价、总股本、净利润）至少两源比对，
   偏差超阈值就告警而不是静默采用。

**数据范围：**
- 行情：日线（分钟线暂不需要，除非做日内，个人投资者不建议）
- 财务：三大报表 + 主要指标，按单季度和 TTM 两种口径
- 基础：股票列表、行业分类、指数成分、上市退市日期
- 宏观：10 年期国债收益率、M2/社融（少量，只取能用的）
- 事件：财报预约披露日、解禁、分红除权、指数调仓
- 文本：公告、政策、研报摘要（存标题+链接+摘要，全文按需）

**存储选型：** DuckDB（列式，适合大批量分析查询，单文件零运维）+ Parquet 归档行情。
业务数据（持仓、交易、日志）同库不同表。不用 Postgres/MySQL，个人项目不值当。

### L2 排除层 — 先排除，再筛选

**放在筛选之前，不是之后。** 先把 5000 只砍到 2000 只，后面所有计算量和噪音都少一大半。

| 规则类型 | 内容 |
|---|---|
| 硬排除 | ST / *ST、退市风险警示、上市不满 N 年、停牌中 |
| 财务红旗 | 经营现金流长期显著低于净利润、应收账款增速远超营收、
存货异常、商誉占净资产过高、审计非标意见、频繁变更会计师 |
| 治理红旗 | 大股东质押比例过高、频繁减持、关联交易占比高、实控人变更频繁 |
| 能力圈边界 | 用户自己声明的「不看的行业」，配置文件写死 |

**能力圈这条是给自己戴的镣铐**，作用是防止未来热点来了给自己找理由破例。必须写在配置里，
修改要留版本记录（见横切层）。

### L3 分析层 — 事实计算

分三个维度，**行业维度不能省**（脱离同行无法判断一家公司好坏）。

**3.1 个股指标**
- 盈利质量：ROE / ROIC（多年序列，看稳定性而非单年）、毛利率净利率趋势
- 现金流质量：经营现金流 / 净利润、自由现金流、应收周转
- 财务健康：资产负债率、有息负债、流动比率、利息保障倍数
- 成长性：营收/利润增速（单季 + TTM，看趋势不看单点）
- 股东回报：分红率、股息率、回购、再融资历史

**3.2 行业横比**（当前架构里最容易被漏掉的一层）
- 同行业内各指标的排名与分位
- 行业集中度、竞争格局变化
- 行业景气度代理指标（价格、产量、下游数据，按行业定制）
- 行业估值历史分位

**3.3 市场水位（宏观读数）**
- 全市场 PE/PB 历史分位
- 股债性价比：全市场 E/P − 10Y 国债收益率
- 用途限定：**只用于设定总仓位上下限，不产生个股买卖信号**

> **明确不做**：宏观择时、牛熊预测、根据宏观数据判断大盘方向。
> 理由：公开证据显示专业机构长期做不好，个人用免费数据只会制造高置信度的噪音。

### L4 研究层 — 估值与观察池

**4.1 估值测算**

DCF 的定位是**反推工具，不是计算器**。核心输出不是「值多少钱」，而是：

> 「要支撑当前股价，这家公司未来 10 年需要保持 X% 的增长率和 Y% 的利润率」

然后由人判断这个假设是否离谱。系统给出隐含假设，人给出判断。

同时提供：相对估值（PE/PB/PS 的历史分位与同行对比）、分红折现（对高分红股）。

**4.2 观察池 ≠ 候选池**

两个不同的东西，必须分开，否则会「筛出来就买」：

| | 候选池 | 观察池 |
|---|---|---|
| 来源 | 筛选器自动产出 | 人工深度研究后加入 |
| 含义 | 值得看一眼 | 已认可，等价格 |
| 附带 | 筛选命中的条件 | 买入理由、核心假设、**证伪条件**、目标价 |
| 动作 | 排队待研究 | 挂价格触发提醒 |

**证伪条件是这层的关键产出**，格式建议：
```
核心假设：X 业务未来三年保持 20%+ 增长，毛利率维持 45% 以上
证伪条件：① 连续两个季度增速低于 10%
         ② 毛利率跌破 40%
         ③ 出现集采/限价类政策
         ④ 大股东减持超过 5%
```
这份东西被 L6 监控层直接消费——监控的不是股价，是**假设是否还成立**。

---

### L5 决策层 — 仓位与约束

**这层比选股更影响最终结果，但最常被忽略。**

**5.1 仓位规则**（配置化，可版本追踪）
- 单票上限 / 单行业上限 / 总仓位上限
- 建仓方式：一次性 or 分批，分批的触发条件
- 加仓规则 —— **必须事先写死**，否则与「摊薄成本」的自我欺骗无法区分
- 总仓位与市场水位（L3.3）的联动区间

**5.2 组合约束检查**
下单前自动校验：这笔买入会不会突破单票/单行业上限、会不会使组合相关性过度集中。
输出是「是否违反已定规则」，不是「建议买多少」。

**5.3 决策日志（强制）**

每笔交易在下单前必须记录：
- 标的、方向、数量、价格
- **买入理由**（自由文本）
- **核心假设**（结构化，供 L6 监控）
- **证伪条件**（结构化，供 L6 监控）
- 当时使用的规则版本号
- 当时的估值读数快照

卖出同样记录理由，并**分类**：假设被证伪 / 估值过高 / 换更好标的 / 纪律止损 / 情绪操作。
最后一类必须诚实填写，它是复盘层最有价值的输入。

---

### L6 监控层 — 持有中

**核心认知：监控的对象是「假设」，不只是「价格」。**

#### 6.0 方法论定位：混合派（已确定）

> **股价下跌 → 寻找原因 → 判断情绪面还是价值面 → 面向未来思考**

这条决定了本层所有行为。与两个极端的区别：

| | 纯价值派 | **本系统（混合派）** | 趋势/技术派 |
|---|---|---|---|
| 下跌时 | 更便宜了，加仓 | **触发调查，结论待定** | 我错了，止损 |
| 决策依据 | 内在价值 | 原因归属 + 前瞻判断 | 价格行为 |
| 风险 | 接住下坠的刀 | 调查拖延、自我合理化 | 卖飞好公司 |

**系统行为定义：**

1. **价格下跌不产生任何买卖信号。** 跌幅只用于确定复核的紧迫级别，不用于确定动作方向。

2. **超过阈值触发「复核任务」**，进入待办队列并计入 SLA（超时未处理会升级提醒）。
   分级建议（具体数值放 `config/position.yaml`）：

   | 触发条件 | 级别 | 处理时限 |
   |---|---|---|
   | 单日跌幅 > A% 或 累计回撤 > B% | P1 | 当日 |
   | 证伪条件命中 / 财报暴雷 / 行业政策冲击 | P0 | 立即 |
   | 跌幅显著大于所属行业（超额下跌） | P1 | 当日，**优先级高于单纯跌幅** |

   注意第三条：**跟随行业下跌和独自下跌，是两种完全不同的事。** 前者大概率是情绪面/贝塔，
   后者往往有个股特定原因。系统应自动做这个拆分，而不是让人从绝对跌幅去猜。

3. **系统准备材料，人做判断。** 复核任务被打开时，自动聚合呈现：
   - 当初的**买入理由、核心假设、证伪条件**（来自 L5 决策日志）
   - 逐条证伪条件的**当前状态核对结果**（能自动判定的自动判定，不能的标注「需人工」）
   - 同期行业与大盘涨跌幅 → 拆出超额跌幅
   - 期间发生的公告、财报、政策、研报调整（含一致预期变动方向）
   - 当前估值分位 vs 买入时估值分位

4. **复核结论必须结构化落库**，三选一：

   | 结论 | 含义 | 后续动作 |
   |---|---|---|
   | **情绪面** | 假设未被动摇，价格与价值背离扩大 | 允许加仓（仍受 L5 仓位上限约束） |
   | **价值面** | 假设已被削弱或证伪 | 减仓 / 清仓，并记录是哪条假设错了 |
   | **信息不足** | 无法判断 | 保持不动 + 设定下次复核时点（必须填，不允许无限期挂起） |

5. **强制前瞻性提问。** 复核表单必填一题：

   > **「以今天的价格、今天掌握的信息，我会重新买入这只股票吗？」**
   >
   > 如果答案是「不会」，那么继续持有的理由是什么？

   这道题的作用是切断沉没成本 —— 把「我亏了 20% 要不要割」重构成「这是不是我今天愿意持有的资产」。
   成本价不参与这个判断，系统在复核界面**默认隐藏持仓成本和浮盈浮亏**（可手动展开）。

6. **纪律止损的适用范围被严格限定。**
   止损只在**「假设被证伪」**时执行，触发条件是基本面事件，不是价格百分比。
   `config/position.yaml` 中允许配置一个**绝对兜底线**（防范黑天鹅和判断完全失效），
   但触发时必须走完复核流程并记录结论，不允许静默机械执行。

**本层最大的失效风险不是逻辑漏洞，是执行**：复核任务积压不处理，
或者每次都填「情绪面」来自我安慰。因此 L8 复盘层必须统计：
复核任务的**及时处理率**、**结论分布**，以及**结论的事后正确率**
（判定为「情绪面」的标的，一年后是否真的修复了）。
这三个数字会诚实地告诉你，你的「寻找原因」到底是分析还是自我安慰。

| 监控类型 | 内容 | 触发源 |
|---|---|---|
| 价格监控 | 观察池到价、持仓异常波动 | 行情数据 |
| 事件日历 | 财报预约披露日、解禁、除权、指数调仓 | 主动排程，非新闻驱动 |
| 基本面事件 | 财报发布、重大公告、行业政策 | 公告/新闻抓取 |
| **假设证伪检查** | 对照 L4 的证伪条件逐条核对 | 财报更新 / 政策事件触发 |
| 组合风险 | 行业集中度、持仓相关性、组合层回撤、总仓位偏离 | 每日计算 |
| 预期差 | 一致预期数值及其调整方向（不看评级） | 研报数据 |

**政策监控的定位**：挂在「假设证伪」链路，不挂在选股链路。
逻辑是「政策发布 → 提醒 → 人回去核对当初的假设是否被打破」，
而不是「根据政策预测哪个板块要涨」。

**组合层风险不可省**：单票止损 -10%、5 只同时触发就是组合 -50%。个股维度的风控管不住这个。

### L7 提醒层 — 分级是生死线

**不分级的提醒系统会自己失效。** 三个月后你会开始无视所有推送，等于系统白做。

| 级别 | 场景 | 渠道 |
|---|---|---|
| P0 立即 | 持仓股财报暴雷、证伪条件命中、重大政策冲击持仓行业 | 手机推送 |
| P1 当日 | 观察池到价、持仓股财报发布、组合约束被突破 | 收盘后汇总 |
| P2 周报 | 筛选器新增候选、指标缓慢变化、系统健康报告 | 周末一封 |

另需：**去重与静默**（同一事件不重复推送、同一标的当日限频）。

---

### L8 复盘层 — 让系统能自我改进

**没有这层，上面所有层都是一套永远不会进化的系统。**

**8.1 交易流水**
完整买卖记录 + 手续费/印花税 + 分红送股，算出真实收益率（不是账户显示的那个）。

**8.2 绩效归因**
把收益拆开，回答「钱是怎么赚到的」：
- 行业配置贡献（买对了赛道）
- 个股选择贡献（同行业内跑赢）
- 择时贡献（进出场时机）

很多人以为自己会选股，拆开发现只是买对了行业。这个拆解直接决定你该改进哪一层。

**8.3 纪律统计**（最毒辣也最有用）
- 胜率、盈亏比、平均持仓周期
- **止损执行率**：写了止损但实际没执行的次数
- **卖出理由分布**：多少比例是「情绪操作」
- 决策日志中的假设，事后被证实/证伪的比例 → 检验你的判断力是否真实存在

**8.3.1 复核质量统计**（混合派定位的配套检验，不可省）

混合派把「下跌怎么办」交给了人的判断，那就必须检验这个判断本身：

| 指标 | 检验什么 |
|---|---|
| 复核任务**及时处理率** | 是否在逃避面对亏损标的 |
| 复核**结论分布** | 「情绪面」占比过高 = 可能在系统性自我安慰 |
| 「情绪面」结论的**事后正确率** | 判为情绪面的标的，N 个月后是否真的修复 |
| 「情绪面」后**加仓的实际结果** | 是价值投资还是在摊薄成本自欺 |
| 「信息不足」的**复核时点兑现率** | 是否借此无限期拖延 |

这几个数字是混合派唯一的防自欺机制。**如果「情绪面」结论的事后正确率长期低于 50%，
说明你的「寻找原因」实际上是在为不愿止损找理由**，此时应当收紧规则、向纯规则化止损靠拢。

**8.4 反哺**
复盘结论要能落回 L2（新增红旗规则）、L4（修正估值假设习惯）、L5（调整仓位规则）。
每次规则修改记录版本号和修改理由。

---

### 横切关注

**配置管理与版本化**
所有规则（筛选条件、仓位上限、止损阈值、能力圈）放配置文件，纳入 git。
每次修改 = 一次 commit + 版本号。决策日志记录当时的版本号。
否则半年后无法区分「业绩变化是市场原因还是我改了规则」。

**调度**
macOS 用 launchd（或 cron）。不上 Airflow —— 个人项目不值当。
任务粒度：盘前（更新基础数据）、盘中（价格监控，按需）、盘后（行情+指标更新）、
周末（全量校验 + 周报）。

**健康检查（不可省）**
数据源失败、任务未执行、某标的数据陈旧超过 N 天 → 主动告警。
**这类失败是静默的，比报错危险得多**——你会以为自己在监控，实际系统早停了。

**日志**
所有数据更新、规则触发、提醒发送留痕，供事后排查。

## 六、实施顺序

按「地基优先 + 价值确定性优先」排，不按功能吸引力排。

| 阶段 | 内容 | 为什么在这个位置 |
|---|---|---|
| **P0** | L1 数据层 + 横切（配置、调度、健康检查） | 一切的前提。复权和公布时间的坑必须一开始就处理对 |
| **P1** | L8 复盘层（交易流水 + 纪律统计） | 价值确定、不会骗你；手动记几笔就开始产生价值，不依赖其他层 |
| **P2** | L2 排除层 + L3 分析层（个股 + 行业） | 纯机械劳动，代码做比人做快且不会漏 |
| **P3** | L6 监控层 + L7 提醒层 | 有了数据和指标才谈得上监控 |
| **P4** | L4 研究层 + L5 决策层（观察池、证伪条件、仓位规则） | 需要前面的积累才知道自己真正需要什么规则 |
| **P5** | L9 Web 看板 | 纯体验改善，最后做 |
| **?** | 回测 | **刻意排在最后**。回测最容易自我欺骗，需要先有足够的怀疑意识和干净的数据基础 |

**关于回测的位置**：常见错误是上来就写策略回测，然后在一个有 bug 的回测里自我陶醉几个月，
再拿真钱去验证。回测放在最后，是为了先建立起对数据和自己判断的怀疑习惯。

## 七、明确不做的事

写下来是为了防止范围蔓延：

- ❌ 自动下单 / 程序化交易
- ❌ 宏观择时、牛熊预测
- ❌ 分钟级/日内数据与策略
- ❌ 机器学习预测股价
- ❌ 任何形式的「推荐买入」输出 —— 系统只提供事实，判断归人
- ❌ 多用户、权限、云部署

## 八、已确定的关键决策

| 决策 | 结论 | 影响范围 |
|---|---|---|
| 方法论定位 | **混合派** —— 下跌触发调查而非动作，判断情绪面/价值面，面向未来思考 | L5、L6、L8 |
| 止损定位 | 仅用于「假设被证伪」，触发条件是基本面事件；价格兜底线需走复核流程 | L6.0 |
| 沉没成本处理 | 复核界面默认隐藏持仓成本与浮盈浮亏 | L6.0 |
| 宏观使用方式 | 仅三个读数用于设定总仓位上下限，不做择时 | L3.3 |
| 政策使用方式 | 挂在假设证伪链路，不做板块预测 | L6 |
