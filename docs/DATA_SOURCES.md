# 数据源实测手册

记录各数据源的**实测状态与已踩的坑**。所有结论来自实际运行，非文档推断。

> 免费数据源的故障是常态而非例外。本文档存在的意义是：
> 让同一个坑只踩一次。

## 二、Point-in-Time 锚点（最重要的结论）

### ✅ 可用：东财「按报告期」详细接口的 NOTICE_DATE

```python
ak.stock_balance_sheet_by_report_em(symbol="SZ300750")  # 319 字段
ak.stock_profit_sheet_by_report_em(symbol="SZ300750")   # 203 字段
ak.stock_cash_flow_sheet_by_report_em(symbol="SZ300750")# 254 字段
```

`NOTICE_DATE` 为财报**首次披露日**，经巨潮原始公告交叉验证一致：

```
宁德时代 2021 年报   NOTICE_DATE  = 2022-04-22
                    巨潮公告时间 = 2022-04-22   ✓
年报滞后 69–118 天，符合 A 股披露规则
```

上市前报告期的 NOTICE_DATE 指向**招股说明书披露日**（宁德时代 2014-2016 年报
均为 2017-11-10），语义正确——上市前财务数据确实到招股书公开时才可得。

### ❌ 不可用：东财**批量**接口的「公告日期」

```python
ak.stock_lrb_em(date="20240930")   # 查 2024Q3
# → 返回的「公告日期」是 2026-08-06、2026-07-25 …
```

**该字段与查询的报告期错位**，给出的是该股票最近一次财报公告的时间。
用于 PIT 会静默产生未来函数——不报错，只让回测收益凭空变好。

批量接口仅可用于 L0 全市场轻量层（不涉及时点回溯的场景）。

### 批量接口的第二个问题：字段严重不足

```
stock_zcfz_em  只有 货币资金/应收账款/存货/总资产/总负债/股东权益
               缺 → 固定资产、在建工程、商誉、合同负债、借款
stock_xjll_em  只有 经营/投资/融资 三个净额
               缺 → 资本开支、折旧
```

缺的恰是红旗规则与行业指标最需要的：**商誉**（减值风险）、**在建工程**
（扩产激进度）、**合同负债**（订单前瞻）、**资本开支**（周期行业核心）。
故核心池必须走逐只详细接口。

## 三、已踩的坑

### 坑 1：请求无限挂起（代价：两次采集报废，约 2.5 小时）

**现象**：进程存活、TCP 连接 ESTABLISHED，但 85 分钟仅消耗 3 秒 CPU，
日志停更且无任何报错。服务器接受连接后不返回数据。

**为何重试机制无效**：重试只能捕获**抛出的异常**，无法处理「永不返回」。

**第一次修复（失败）**：`socket.setdefaulttimeout(45)`

失败原因值得记住：urllib3 在建立连接后会显式调用
`sock.settimeout(<requests 传入的 timeout>)`，**覆盖全局默认值**；
而 akshare 显式传 `timeout=None`，等同于把 socket 重设为永久阻塞。
全局设置根本没有机会生效。

**正确修复**：在 requests 层拦截。

```python
original = requests.Session.request
def patched(self, *args, **kwargs):
    if kwargs.get("timeout") is None:      # 覆盖 None，不是 setdefault
        kwargs["timeout"] = 30
    return original(self, *args, **kwargs)
requests.Session.request = patched
```

已验证：`timeout=None` 的请求 21 秒抛异常，不再挂起。

### 坑 2：东财限流封禁

**现象**：短时间大量请求后，东财对**所有**接口持续返回
`RemoteDisconnected`。实测行情接口连续 4 只股票全部失败，重试与
60 秒静置均无效。

**触发阈值**（实测）：以 0.6 秒间隔连续请求约二十次即触发。

**应对**：
- 全局最小请求间隔 1.5 秒
- 连续失败 6 次判定为限流，静置 60 秒
- **切换到 baostock** —— 这是唯一真正有效的手段，因为封禁按 IP 计，
  换接口无用，必须换数据服务商

### 坑 3：接口整体失效

`stock_board_industry_name_em`（东财行业板块）重试 5 次全部失败，
接口本身已废。

**替代方案**：从 `stock_yjbb_em`（业绩报表）的「所处行业」字段获取，
该接口批量返回且自带行业分类。

### 坑 4：股票列表接口不稳定

`stock_info_a_code_name` 首次调用 SSL 握手失败，`stock_zh_a_spot_em`
连接中断。但**重试后前者成功**。

**应对**：多接口 fallback（`first_success`），三个候选依次尝试。

### 坑 5：日志管道缓冲导致误判

`command | grep pattern > log` 中，grep 默认块缓冲（4KB），
日志看起来长时间不更新，与真正的挂死难以区分。

**应对**：`python -u` + `grep --line-buffered`。
**无可观测性的长任务无法判断健康状况——这本身就是缺陷。**

## 四、研报数据边界

```
数据量    202 条/只（均值），604 只推算约 12 万条
时间跨度  普遍到 2017 年，接近 9 年
耗时      3.5 秒/只
```

### 评级分布（实测）

```
买入 94%  |  增持 5%  |  持有 1%
```

绝对评级几乎不携带信息量。有价值的是**评级调整**（尤其下调，
逆着分析师的激励机制）。

### ❌ 无目标价字段

接口提供预测 EPS 与预测 PE，但实测同期不同机构的乘积高度一致：

```
2026-07-31 国信证券  EPS 20.83 × PE 19.30 = 402.0
2026-07-29 山西证券  EPS 21.28 × PE 18.40 = 391.6
2026-07-28 西南证券  EPS 19.65 × PE 20.36 = 400.1
```

若 PE 是各家给出的目标估值，乘积作为目标价理应显著分歧。
如此接近只能说明：**预测PE = 发布日股价 ÷ 预测EPS**。

故「是否涨到目标价」无法验证。目标价仅存在于 PDF 正文。

### ❌ 历史盈利预测不可回溯

```
2018-2023 年发布的研报：预测字段非空率 0%
2024 年：86%   2025 年：89-95%   2026 年：92-96%
```

接口只返回「对当前及未来年份的预测」。**从现在开始存快照是唯一出路**——
`research_forecast` 表以 `snapshot_date` 入主键正是为此，
一年后即拥有一段买不到的一致预期序列。

## 五、baostock 注意事项

```python
adjustflag = "1"  # 后复权
adjustflag = "2"  # 前复权
adjustflag = "3"  # 不复权
```

- 会话是**进程级全局状态且非线程安全**，需加锁串行化
- 复权因子由「后复权收盘 / 不复权收盘」反推。其
  `query_adjust_factor` 返回的是除权除息明细而非逐日因子，
  逐日展开反而更易出错
- K 线接口可附带 `peTTM / pbMRQ / psTTM`，正好填补 akshare
  缺少历史 PE 批量接口的空缺
- ⚠️ **与东财的复权算法不完全一致，同一只股票不可混用两源**，
  否则会在拼接处产生虚假价格跳变。故按股票整体选源。

## 复权口径：三种价格的用途互不重叠

**2026-08-16 实测事故**：前端显示 300568 于 2026-08-14 开盘 106.56，
券商 App 显示 14.51。库中数据无误（原始价与因子分列存储），
错在展示层直接输出了 `close * adj_factor`。

| 口径 | 计算 | 唯一正确用途 | 用错的后果 |
|---|---|---|---|
| 原始价 | `close` | 与研报同期数据对齐 | 除权日出现虚假断崖 |
| 后复权 | `close * adj_factor` | **算收益率、技术指标** | 当价格显示 → 300568 差 7.34 倍 |
| 前复权 | `close * adj_factor / 末日因子` | **唯一可展示的口径** | 落盘 → 未来除权会改写历史值 |

### 为什么回测必须用后复权

前复权与后复权的**收益率完全相同**——二者只差一个每只股票固定的常数，
在 `p1/p0 - 1` 中约掉。实测同区间差异 `0.00e+00`。

但**前复权的历史值会随未来的除权事件改变**：今天跑出的回测结论，
下次送转后重跑就变了，不可复现。故回测一律用后复权，且**只取比值**。

已核查全部使用点，均为 `p1/p0 - 1` 形式，无一处使用绝对价格：
`cycle_study.py:203` / `screen_backtest.py:178` /
`research_study.py:91` / `events/detector.py:249`。

### 展示层的归一化基准，两处不同

- **个股 K 线** → 基准取**全序列最新一日**。
  若按请求区间末日归一，缩放时间轴时纵轴会整体漂移
  （查 2016 得 31.18，查至今得 4.25）。
- **研报分析页 K 线** → 基准取**研报发布日**。
  该页要把预测隐含价标注在 K 线上，而那是发布当时的价格。
  实测 2017-01-17 东兴证券那份：真实价 75.60，
  修复前 K 线画在 555.20，标注全部错位。

## ⚠️ 尚未踩到的坑：EPS 预测的口径

研报表中**没有目标价字段**，预测只有 `eps` 与 `pe`：

- `pe` 是比值（价格/EPS），分子分母同期，**与复权无关**，可直接跨期比较
- `eps` 是**发布当时股本口径**的每股收益，**不可直接与后期实际 EPS 比较**

300568 的股本：**0.9 亿股（2012）→ 13.46 亿股（2026），扩张 14.95 倍**
（含 IPO、送转、增发；`adj_factor` 只反映其中的除权部分，为 7.34）。

拿 2017 年研报预测的 EPS 直接对比 2019 年实际 EPS，
研报会被**系统性判为高估**——但那不是预测错了，是分母变了。

正确做法二选一：
1. 预测 EPS × 当时股本 = 预测净利润，与实际净利润比较（推荐，口径干净）
2. 用复权因子还原 EPS（仅能处理送转，处理不了增发）

`src/csg/validation/` 中**目前没有任何 EPS 准确度验证**（已 grep 确认）。
实现时若忽略本节，会得到「所有机构都高估盈利」的假结论。

## 事故：DuckDB 区块统计损坏（2026-08-16，已修复，未造成损害）

`research_report.publish_date` 与三张 `fin_*.disclosure_date` 的
区块统计（zone map）损坏，导致优化器跳过实际含匹配行的数据块：

```
SELECT count(*) FROM research_report WHERE publish_date >= DATE '2025-06-01'
  →   20      （错误，剪枝跳过了含匹配行的块）
SELECT count(*) FROM research_report WHERE publish_date + INTERVAL 0 DAY >= ...
  → 1647      （正确，表达式破坏了下推）
```

**影响范围经实测为零**：该损坏只作用于**单边比较且不带上界**的查询形态，
而生产代码全部使用 `BETWEEN` 双边界，剪枝结果正确。三处决定性核对
（备份库 vs 修复后）：

- `validation/research_study.report_outcomes`：发现期 9865 / 验证期 7480，**两库一致**
- `/api/reports` 三个日期区间的 total：**两库一致**
- 故此前的研报验证结论**依然有效**，无需重跑

修复方法：导出 parquet → DROP → 按原 DDL 重建 → 灌回 → CHECKPOINT。
重建后所有日期列的下推与全扫描结果一致。
备份：`data/backup/csg_before_statfix_20260816.duckdb`

**诊断手法值得记住**：比较 `col >= X` 与 `col + INTERVAL 0 DAY >= X`。
后者阻止谓词下推，二者不等即说明统计信息不可信。
这类损坏不报错——与本项目其他静默失效同型。

## ⚠️ 研报数据的系统性缺失：所有头部券商都不在样本里

**2026-08-16 发现。这一条限定了本项目全部研报结论的适用范围。**

数据源：`ak.stock_research_report_em`（东方财富个股研报页）。
经直接调用接口核对（宁德时代 300750）：接口返回 469 条、库中 469 条，
**采集完整无遗漏**。问题在源头——接口返回的 39 家机构中，
以下券商**一家都没有**：

```
中信证券 ❌   中金公司 ❌   华泰证券 ❌   国泰君安 ❌
招商证券 ❌   广发证券 ❌   海通证券 ❌   兴业证券 ❌
申万宏源 ❌   东方证券 ❌
```

（库中「中金财富」5 条是中金的财富管理子公司，不是中金研究部。）

库中 69 家全部为中小券商：东吴 2755、民生 1897、国金 1303、开源 1270……

**成因推断**：头部券商的研究报告是卖给付费机构客户的核心产品，
不授权免费公开渠道转发；中小券商则把东财当作获客与曝光渠道。
即样本不是随机缺失，而是**按「研究能否卖钱」系统性筛选过的**。

### 对已有结论的影响

已验证的结论在样本内依然成立，但**适用范围必须限定**：

| 结论 | 正确表述 |
|---|---|
| 机构排名不可复现（秩相关 −0.366） | 限于**东财免费渠道的中小券商**之间 |
| 跟着研报买年化 3.74%，跑输创业板指 | 同上 |
| 评级无区分度（买入占 99.33%） | 同上——头部券商评级分布可能不同 |

**没有被证伪的是**：头部券商的研究是否有价值——我们从未观察到过它。
不可由「中小券商研报无预测力」推出「券商研报无预测力」。
