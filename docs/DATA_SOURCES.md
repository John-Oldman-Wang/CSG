# 数据源实测手册

记录各数据源的**实测状态与已踩的坑**。所有结论来自实际运行，非文档推断。

> 免费数据源的故障是常态而非例外。本文档存在的意义是：
> 让同一个坑只踩一次。

## 二、Point-in-Time 锚点（最重要的结论）

### ✅ 可用：东财「按报告期」详细接口的 NOTICE_DATE

```python
ak.stock_balance_sheet_by_report_em(symbol="SZ300750")  # 319 字段
ak.stock_profit_sheet_by_report_em(symbol="SZ300750")   # 203 字段
ak.stock_cash_flow_sheet_by_report_em(symbol="SZ300750")# 254 字段
```

`NOTICE_DATE` 为财报**首次披露日**，经巨潮原始公告交叉验证一致：

```
宁德时代 2021 年报   NOTICE_DATE  = 2022-04-22
                    巨潮公告时间 = 2022-04-22   ✓
年报滞后 69–118 天，符合 A 股披露规则
```

上市前报告期的 NOTICE_DATE 指向**招股说明书披露日**（宁德时代 2014-2016 年报
均为 2017-11-10），语义正确——上市前财务数据确实到招股书公开时才可得。

### ❌ 不可用：东财**批量**接口的「公告日期」

```python
ak.stock_lrb_em(date="20240930")   # 查 2024Q3
# → 返回的「公告日期」是 2026-08-06、2026-07-25 …
```

**该字段与查询的报告期错位**，给出的是该股票最近一次财报公告的时间。
用于 PIT 会静默产生未来函数——不报错，只让回测收益凭空变好。

批量接口仅可用于 L0 全市场轻量层（不涉及时点回溯的场景）。

### 批量接口的第二个问题：字段严重不足

```
stock_zcfz_em  只有 货币资金/应收账款/存货/总资产/总负债/股东权益
               缺 → 固定资产、在建工程、商誉、合同负债、借款
stock_xjll_em  只有 经营/投资/融资 三个净额
               缺 → 资本开支、折旧
```

缺的恰是红旗规则与行业指标最需要的：**商誉**（减值风险）、**在建工程**
（扩产激进度）、**合同负债**（订单前瞻）、**资本开支**（周期行业核心）。
故核心池必须走逐只详细接口。

## 三、已踩的坑

### 坑 1：请求无限挂起（代价：两次采集报废，约 2.5 小时）

**现象**：进程存活、TCP 连接 ESTABLISHED，但 85 分钟仅消耗 3 秒 CPU，
日志停更且无任何报错。服务器接受连接后不返回数据。

**为何重试机制无效**：重试只能捕获**抛出的异常**，无法处理「永不返回」。

**第一次修复（失败）**：`socket.setdefaulttimeout(45)`

失败原因值得记住：urllib3 在建立连接后会显式调用
`sock.settimeout(<requests 传入的 timeout>)`，**覆盖全局默认值**；
而 akshare 显式传 `timeout=None`，等同于把 socket 重设为永久阻塞。
全局设置根本没有机会生效。

**正确修复**：在 requests 层拦截。

```python
original = requests.Session.request
def patched(self, *args, **kwargs):
    if kwargs.get("timeout") is None:      # 覆盖 None，不是 setdefault
        kwargs["timeout"] = 30
    return original(self, *args, **kwargs)
requests.Session.request = patched
```

已验证：`timeout=None` 的请求 21 秒抛异常，不再挂起。

### 坑 2：东财限流封禁

**现象**：短时间大量请求后，东财对**所有**接口持续返回
`RemoteDisconnected`。实测行情接口连续 4 只股票全部失败，重试与
60 秒静置均无效。

**触发阈值**（实测）：以 0.6 秒间隔连续请求约二十次即触发。

**应对**：
- 全局最小请求间隔 1.5 秒
- 连续失败 6 次判定为限流，静置 60 秒
- **切换到 baostock** —— 这是唯一真正有效的手段，因为封禁按 IP 计，
  换接口无用，必须换数据服务商

### 坑 3：接口整体失效

`stock_board_industry_name_em`（东财行业板块）重试 5 次全部失败，
接口本身已废。

**替代方案**：从 `stock_yjbb_em`（业绩报表）的「所处行业」字段获取，
该接口批量返回且自带行业分类。

### 坑 4：股票列表接口不稳定

`stock_info_a_code_name` 首次调用 SSL 握手失败，`stock_zh_a_spot_em`
连接中断。但**重试后前者成功**。

**应对**：多接口 fallback（`first_success`），三个候选依次尝试。

### 坑 5：日志管道缓冲导致误判

`command | grep pattern > log` 中，grep 默认块缓冲（4KB），
日志看起来长时间不更新，与真正的挂死难以区分。

**应对**：`python -u` + `grep --line-buffered`。
**无可观测性的长任务无法判断健康状况——这本身就是缺陷。**

## 四、研报数据边界

```
数据量    202 条/只（均值），604 只推算约 12 万条
时间跨度  普遍到 2017 年，接近 9 年
耗时      3.5 秒/只
```

### 评级分布（实测）

```
买入 94%  |  增持 5%  |  持有 1%
```

绝对评级几乎不携带信息量。有价值的是**评级调整**（尤其下调，
逆着分析师的激励机制）。

### ❌ 无目标价字段

接口提供预测 EPS 与预测 PE，但实测同期不同机构的乘积高度一致：

```
2026-07-31 国信证券  EPS 20.83 × PE 19.30 = 402.0
2026-07-29 山西证券  EPS 21.28 × PE 18.40 = 391.6
2026-07-28 西南证券  EPS 19.65 × PE 20.36 = 400.1
```

若 PE 是各家给出的目标估值，乘积作为目标价理应显著分歧。
如此接近只能说明：**预测PE = 发布日股价 ÷ 预测EPS**。

故「是否涨到目标价」无法验证。目标价仅存在于 PDF 正文。

### ❌ 历史盈利预测不可回溯

```
2018-2023 年发布的研报：预测字段非空率 0%
2024 年：86%   2025 年：89-95%   2026 年：92-96%
```

接口只返回「对当前及未来年份的预测」。**从现在开始存快照是唯一出路**——
`research_forecast` 表以 `snapshot_date` 入主键正是为此，
一年后即拥有一段买不到的一致预期序列。

## 五、baostock 注意事项

```python
adjustflag = "1"  # 后复权
adjustflag = "2"  # 前复权
adjustflag = "3"  # 不复权
```

- 会话是**进程级全局状态且非线程安全**，需加锁串行化
- 复权因子由「后复权收盘 / 不复权收盘」反推。其
  `query_adjust_factor` 返回的是除权除息明细而非逐日因子，
  逐日展开反而更易出错
- K 线接口可附带 `peTTM / pbMRQ / psTTM`，正好填补 akshare
  缺少历史 PE 批量接口的空缺
- ⚠️ **与东财的复权算法不完全一致，同一只股票不可混用两源**，
  否则会在拼接处产生虚假价格跳变。故按股票整体选源。
