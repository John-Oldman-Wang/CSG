## A. 阻塞项 —— 这几项没做完，P0 数据层无法开工

### A1. 磁盘空间清理 ⚠️ 优先级最高

**当前状态：228 GB 容量，已用 84%，仅剩 34 GB。**

这不只是「放不下数据」的问题。真正的原因是：

> 8 GB 内存下，DuckDB 必须依赖 **out-of-core（溢写磁盘）** 才能处理超过内存的数据集。
> 磁盘临时空间不足会导致查询直接失败，而不是变慢。

同时 macOS 在可用空间低于 10% 时会出现系统级性能退化。

**要求：清理到至少 60 GB 可用。** 建议检查方向：

```bash
du -sh ~/Library/Caches ~/Library/Developer ~/Downloads ~/Documents 2>/dev/null | sort -h
```

常见大户：Xcode 模拟器与 DerivedData、Docker 镜像、iOS 设备备份、
Downloads 积压、大型 node_modules、Time Machine 本地快照。

> 你可以让 Claude 帮你分析磁盘占用并列出清理候选，但**删除操作由你确认后执行**。

### A2. tushare pro 账号与积分

已确认愿意投入约 200 元/年。

**步骤：**

1. 注册 <https://tushare.pro>
2. 完成实名认证（获取基础积分需要）
3. 在「个人主页 → 接口权限」查看当前积分与可用接口
4. 充值至满足财务数据接口的积分门槛

**⚠️ 注意**：tushare 的积分门槛和定价规则会调整，请以**你注册时官网显示的当前规则**为准。
重点确认这几类接口是否已解锁：

| 接口类别 | 用途 | 对应层 |
|---|---|---|
| `daily` / `adj_factor` | 日线行情、复权因子 | L1 |
| `stock_basic` / `namechange` | 股票列表、更名历史 | L1 |
| `income` / `balancesheet` / `cashflow` | 三大报表 | L1 → L3 |
| `fina_indicator` | 财务指标 | L3 |
| `disclosure_date` | **财报实际公布日** | L1（防未来函数的关键） |
| `suspend_d` / `stk_limit` | 停牌、涨跌停价 | L1 |

**产出给我**：一个 API Token（字符串），我会写入 `config/secrets.yaml`（已 gitignore）。

> **Token 属于密钥。** 请直接粘贴给我即可，不要提交到任何公开位置。

### A3. 飞书自定义机器人 Webhook

**步骤：**

1. 飞书中新建一个群（建议只有你自己，命名如「CSG 提醒」）
2. 群设置 → **群机器人** → 添加机器人 → **自定义机器人**
3. 命名（如 CSG），复制 **Webhook 地址**
4. 安全设置建议开启 **签名校验**，复制 **签名密钥**

> 三种安全设置中选「签名校验」。「自定义关键词」会限制消息内容，
> 「IP 白名单」在家用宽带动态 IP 下不可用。

**产出给我**：Webhook URL + 签名密钥。

**建议同时建两个群 / 两个机器人**，对应提醒分级：

| 群 | 接收 | 手机通知设置 |
|---|---|---|
| CSG-紧急 | P0（证伪命中、财报暴雷、政策冲击） | 开启强提醒 |
| CSG-日常 | P1 / P2（复核任务、到价、周报） | 普通或免打扰 |

分开的理由：**如果 P0 和 P2 混在一个群，三个月后你会关掉整个群的通知，系统等于白做。**

## B. 重要项 —— 影响系统能否产生真实价值

### B1. 历史交易记录导出 📌 价值最高的一项

如果你此前已有 A 股交易，**把历史成交记录导出来**。

理由：L8 复盘层是实施顺序里的 P1（仅次于数据层）。有了历史数据，
系统第一天就能告诉你真实的胜率、盈亏比、平均持仓周期、卖出理由分布——
**这些结论不依赖任何后续开发，且往往比任何选股功能更能改善你的收益。**

**获取方式**：券商 App/网页版 → 交割单 / 历史成交 / 对账单 → 导出 Excel 或 CSV。
尽量导全（含手续费、印花税、分红派息记录）。

**产出给我**：CSV/Excel 文件放到项目任意位置，告诉我路径。我会写导入脚本适配你的券商格式。

> **系统不接券商账户，不需要你的券商账号密码，不做任何自动交易。**
> 只读取你手动导出的历史文件。

### B2. 能力圈边界声明

写下**你不看的行业**，会写进 `config/universe.yaml`。

这个的作用不是筛数据，是**给未来的自己戴镣铐**——防止某天热点来了自己给自己找理由破例。
配置纳入 git，每次修改留记录，复盘时能看到你破了几次戒。

格式随意，例如：
- 不看：银行、保险、券商（看不懂）
- 不看：影视、游戏（现金流无法预测）
- 不看：市值 < 50 亿（流动性与治理风险）

如果暂时想不清楚，可以先留空，用一段时间后再补。

需要你给出数值，会写进 `config/position.yaml`：

| 参数 | 说明 | 参考 |

### B4. 复核触发阈值

混合派的核心参数——什么程度的下跌触发复核任务：

| 参数 | 说明 |
|---|---|
| 单日跌幅阈值 | 超过即触发 P1 复核 |
| 累计回撤阈值 | 从买入价或高点回撤多少触发 |
| **超额下跌阈值** | 跌幅超过所属行业多少个百分点（**这项比绝对跌幅更重要**） |
| 复核处理时限 | 任务多久未处理升级提醒 |
| 绝对兜底止损线 | 黑天鹅防线，触发仍需走完复核流程 |

同样可以先用默认值起步。

## C. 可选项 —— 提升可靠性

### C1. GitHub 私有仓库（用于 journal 备份）

`journal/`（决策日志、交易记录）是系统中**唯一不可再生**的数据。
行情丢了能重拉，你三年前为什么买某只股票的记录丢了就永久损失。

需要你创建一个**私有**仓库并授权推送。健康检查会监控「最后成功推送距今天数」。

### C2. 电源与休眠设置

当前设置：Power Nap 已开启，标准睡眠模式。

架构上任务已设计为幂等自愈（见 ARCHITECTURE.md 4.3），**不依赖调度准时**，
所以这项不做也能正常工作。若希望盘后任务更大概率准时执行，可考虑在交易日盘后时段
接电源不合盖。属于锦上添花，非必需。

### C3. Xcode Command Line Tools

若尚未安装，某些 Python 包在缺少预编译轮子时需要它来编译。
M1 上主流库均有 arm64 轮子，大概率用不到，作为兜底：

```bash
xcode-select --install
```
